# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`com.helger:parser-generator-cc` — a maintained fork of JavaCC 7.0.3, base package renamed
`net.javacc` -> `com.helger.pgcc`. Single Maven module, currently `2.0.2-SNAPSHOT`, parent POM
`com.helger:parent-pom:3.1.0`. Java baseline 17. Maintenance mode: changes are made mainly when
something breaks, primarily for its main consumer [ph-css](https://github.com/phax/ph-css).

## Build and test

Run everything from the repository root — tests use relative paths (`grammars`, `examples`,
`src/test/resources/issues/...`, `src/main/resources`, `www/doc/`) and fail elsewhere.

```
mvn clean install          # full build
mvn test                   # tests
mvn test -Dtest=Issue33Test
mvn license:check          # BSD header check; NOT bound to any phase, must be run explicitly
mvn license:format         # fix missing/outdated headers
```

There is no formatter, linter or build CI in this project — `mvn license:check` is the only
automated style gate. PMD/SpotBugs exist only in the parent's `<reporting>` (`mvn site`).

### Test side effects — always clean up

`mvn test` dirties the working tree. After a test run:

```
git checkout -- www/doc/            # JJDocMainTest overwrites JavaCC.html + JavaCC.txt
rm -f JavaCCParserTokenManager.java # stray root output (gitignored, but noisy)
```

Never commit the regenerated `www/doc/JavaCC.html` / `JavaCC.txt` — they are test noise.

## Code generation and the bootstrap footgun

`ph-javacc-maven-plugin:5.0.1` runs at `generate-sources` and produces the parser from
`src/main/javacc/{JavaCC.jj,ConditionParser.jj}` and `src/main/jjtree/JJTree.jjt` into
`target/generated-sources/`. Generated sources are **not** checked in — never edit
`target/generated-sources/**`; edit the `.jj` / `.jjt` sources.

**The project is generated by a released version of itself.** `ph-javacc-maven-plugin:5.0.1`
bundles `parser-generator-cc:2.0.1`. A change to grammar handling or code generation therefore does
*not* affect this project's own build until `parser-generator-cc` is released and a new
`ph-javacc-maven-plugin` picks it up. Do not assume a codegen change is self-applying, and do not
"fix" a build failure by assuming the local generator was used.

## Templates

`src/main/resources/templates/` holds the emitted output. Parallel variants exist and drift apart
easily — when changing one, check the others:

- `stream/java/` (classic) and `stream/java/modern/` — near-identical; a fix in one almost always
  belongs in the other.
- `stream/cpp/` — derived from the same JavaCC ancestor; useful as a cross-check when the Java side
  looks wrong.
- `*.template` files are excluded from the license header check and use `#if`/`#fi` preprocessor
  directives, not Java syntax.

Tests that must read the checkout's templates rather than an older `parser-generator-cc` jar on the
classpath call `FilesJava.setReadFromClassPath (false)` and restore it afterwards — it is a static
global, so restore it in a `finally` / `@AfterClass`.

## Code style

Follow the global rules in `~/.claude/rules/naming.md` (Hungarian notation, `_privateMethod`, space
before `(`, `LOGGER` with string concatenation, `final` parameters), **with one override**:

- The license header is **BSD**, not Apache 2.0. Copy it from `src/etc/license-template.txt`
  (Philip Helger 2017-2026 + Google 2011 + Sun Microsystems 2006). `strictCheck` is on.
- Null annotations are **JSpecify** (`org.jspecify.annotations.NonNull` / `Nullable`).
- Upstream JavaCC code that has not been reworked does not follow the house style. Match the
  surrounding file rather than reformatting it.

Test naming: `*FuncTest` for slow generate-compile-run functional tests, `*Test` for the rest.

## Repo etiquette

- Work directly on `main`; no feature branch, no PR.
- Update the `# News and noteworthy` section of `README.md` for every library change. There is no
  `../ParserGeneratorCC.wiki` checkout. The current entry is `v2.0.2 - work in progress`; append a
  bullet to it in the existing style.

## Ignore these directories

`test/` (dead Ant `build.xml` from upstream), `examples/`, and `grammars/` are legacy. Do not read
or modify them unless explicitly asked.
